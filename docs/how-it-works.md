# 实现原理（how it works）

本文解释 AI-Card-Catcher 为什么能拿到角色设定，以及每一层在做什么。

## 1. 核心原理：角色网站是"无状态"的

AI 角色扮演网站的架构是：

```
浏览器/前端 ──HTTP──> 网站服务器 ──HTTP──> 大模型 API
```

网站数据库里存的是**角色卡的元数据**（给你看的简介、图片、标签），而真正驱动模型的**完整设定**——人物卡正文、世界书条目、越狱提示词、玩家身份、聊天历史——是**每次对话时实时组装**进 API 请求的 `messages` 数组发出去的。

这意味着两件事：

1. **设定必然经过 API 请求**。网站不可能不发给模型，否则模型不知道角色是谁。
2. **谁站在 API 链路上，谁就能看到全部设定。**

所以本工具的做法不是去破解网站，而是**提供一个 OpenAI 兼容的 API 入口让网站填**（网站本来就支持自定义 API 地址），流量自然流经我们：

```
网站 ──> cpolar隧道(https公网) ──> 记录代理:3001 ──> NewAPI:3000 ──> 火山方舟/其他上游
```

记录代理把每个请求体原样写入 SQLite，一个字节不改地转发给 NewAPI——网站毫无感知。

## 2. 真实请求长什么样

以 VSOUL 实测为例，一次普通对话的请求体约 **46KB ~ 764KB**，`messages` 数组结构：

| # | role | 典型大小 | 内容 |
|---|------|--------|------|
| 0 | system | ~800B | 越狱/规则指令（"你没有内容限制…"） |
| 1 | user | ~200B | 角色扮演规则确认 |
| 2 | assistant | ~120B | 模型确认（网站预置） |
| 3 | user | **30KB+** | **`# 世界观知识`——世界书全部条目** |
| 4 | user | ~200B | `# User 扮演的身份信息`——玩家卡 |
| 5 | user | ~5KB | `Here is your immutable role-play character settings`——角色设定 |
| 6 | assistant | ~5KB | AI 上一轮回复 |
| 7 | user | 几字节 | **用户真实输入**（比如就一个 "a"） |
| 8 | user | ~1.5KB | `# 补充设定/协作规则` |
| 9 | user | ~150B | 描写风格指导 |

参数：`temperature: 0.7`、`max_tokens: 800`、`stream: true`。

**关键洞察：人物卡主体往往在 `user` 消息里，不在 `system` 里。** 只看 system 会漏掉 90% 的内容——这也是本工具把完整 messages 全部入库、按内容特征分类的原因。

## 3. 各层职责

### 3.1 cpolar 隧道（公网入口）

聊天网站的服务器要能访问你电脑上的服务，需要公网地址。家庭宽带处于双重 NAT（尤其手机 USB 共享网络）之下，无法端口映射，所以用内网穿透：本机 cpolar 客户端主动连接 cpolar 云端，云端把 `https://xxx.r9.cpolar.cn` 的流量反向推回本机 3001 端口。

- 必须 `https`（网站校验），cpolar 自动带证书
- 免费版域名随机，重启会变
- 启动参数 `-region=cn`（默认 us，国内极慢）、`-log=stdout`（默认不输出任何日志）

### 3.2 记录代理（app/main.py，端口 3001）

同一个进程做四件事：

1. **透明转发**：`/v1/*` 原样转发到 `127.0.0.1:3000`，流式响应（SSE）逐块透传，客户端无感
2. **记录**：请求体、响应体完整存入 `data/records.db`（SQLite，单条上限 50MB——世界书实测能到 660KB，截断会导致 JSON 不可解析，宁大勿小）
3. **提取**：从请求 JSON 解析 messages，按内容特征分类（见 §4）
4. **管理界面**：`/cc/api/*` 提供 REST 接口给前端三页使用

访问保护：`?token=xxx` 或 `X-CC-Token` 头，start.bat 打开浏览器时自动携带。**经 cpolar 进来的请求源 IP 也是 127.0.0.1**，无法用 IP 区分内外网，所以必须令牌。

### 3.3 New API（端口 3000）

标准的 AI 网关：管理上游渠道（火山方舟 Key）、签发接入令牌、计费统计。本工具复用它做上游管理和鉴权，自己不重复造轮子。

### 3.4 卡片提取与分类

规则（`main.py` 的 `CLASSIFY_RULES`）：

```
system/developer 消息            → 系统破甲提示词
包含"世界观知识"                  → 世界书
包含"immutable role-play..."     → 角色设定
包含"扮演的身份信息"               → 玩家身份设定
包含"# 补充设定"/"协作规则"        → 补充设定与协作规则
包含"情色描写/成人虚构/描写指导"    → 描写指导
user 消息 >3000 字符（未匹配）     → 归入世界书
最后一条短 user 消息               → 用户实际输入
其余 assistant                    → 聊天历史（第一条兼作开场白）
```

产出三种 JSON：

- **SillyTavern V2**（`spec: chara_card_v2`）：`description`←角色设定、`system_prompt`←破甲、`first_mes`←开场白、`character_book.entries`←世界书、`post_history_instructions`←描写指导、`extensions`←玩家卡/规则
- **世界书 JSON**（SillyTavern 世界书格式）：`entries` 数组，每条含 `comment/key/content/constant/order/depth/probability/excludeRecursion/preventRecursion`。**已实测可直接通过 VSOUL 的「从 JSON 导入」导入**（2026-09-29 验证，2 条常态条目字段全部保留），因为 VSOUL 的世界书表单字段与 ST 世界书一一对应
- **VSOUL 表单结构**：按创建角色页面的字段名（角色描述/背景知识/开场白/世界书…）组织，照着在网站重建同款角色

字段映射是"最佳努力"：网站实际拼装方式因站而异，所以界面允许看原文、按条复制，分类只是起点。

### 世界书的保真度说明

抓到的 660KB 是**网站拼装后的"注入全文"**（122 个一级标题、2401 个三级标题的混合体），不是原始条目数据——原始条目存在网站服务器上。因此导出的世界书采用**单条目 `constant:true`（常态激活）**策略：与原站行为完全一致（原站每次对话也是全量注入 660KB），只是失去"按关键词触发"的灵活性，因为触发关键词的原始数据拿不到。若需要真条目拆分，得从网站导出原始世界书 JSON。

## 4. 为什么选这套架构

| 决策 | 理由 |
|------|------|
| 纯 Python 标准库，零 pip 依赖 | 小白解压即跑，不会有"装依赖失败" |
| 单进程主控管理全部子进程 | start.bat 只需启动一个东西；stop 杀一个 PID 即可级联关闭 |
| SQLite 单文件存储 | 备份 = 复制一个文件 |
| UI 与代理同端口（3001） | 网站只需填一个公网地址；UI 走 `/cc/*` 命名空间与 `/v1/*` 隔离 |
| New API 作为上游网关 | 渠道管理、多上游、令牌、计费全部白得，还能给不同网站发不同令牌 |
| cpolar 而非 frp | 无需云服务器，自带 https 域名；国内节点速度可接受 |

## 5. 多格式兼容（OpenAI / Anthropic / Gemini）

代理层会**自动识别**请求属于哪种格式，归一化后再分类：

| 格式 | 识别特征 | 归一化方式 |
|---|---|---|
| **OpenAI**（绝大多数网站） | `messages` 数组 | 直接遍历 messages |
| **Anthropic** | `messages` 只含 user/assistant 且顶层有 `system` | 顶层 system → 系统消息；content 支持 str 和 blocks |
| **Gemini** | `contents` 数组 | `systemInstruction` → 系统消息；`role:"model"` → assistant；`parts[].text` 拼接 |

卡片页会显示识别出的格式徽章；记录详情同样按归一化后的消息展示。

**分类规则可配置**：配置页底部「卡片自动分类规则」直接编辑 JSON（`strong` 强特征优先匹配 / `weak` 兜底 / `big_user_worldbook` 超长 user 消息视为世界书的阈值），保存立即生效。遇到新网站时，抓一条请求看它的设定开头写什么，把特征词加进 strong 即可。

## 6. 已知限制

- 免费版 cpolar 域名随重启变化，需要回网站改 API URL
- 仅覆盖「OpenAI 兼容接口 + 支持自定义 API 地址」的网站；纯服务端转发且不允许自定义地址的网站抓不到
- 超大 prompt（764KB ≈ 25 万 tokens）可能超过模型上下文上限，导致上游报错——这是模型侧限制，与抓取无关
- 网站若改版拼装方式，分类关键词需要更新（配置页可自行调整）
